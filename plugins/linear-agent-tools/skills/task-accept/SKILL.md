# Accept Linear Outcome

Accept one `task:acceptance` / `evidence` issue in a fresh `gpt-5.6-sol` max-reasoning thread. Read `../../references/manual-workflow.md`, the complete active Project graph, exact source revision, every resulting stable owner, merged commits, current external state and direct evidence.

1. Set canonical `LINEAR_AGENT_WORKSPACE_ROOT`, acquire the exact issue process-lifetime guard before dispatch/status mutation, and hold it through nested cleanup and final provider readback. Process exit afterward is the only release.
2. Fully reread Linear, run dispatch, require Project `In Progress`, issue `Todo`/`In Progress`/`Rework`, exact acceptance role/evidence delivery and no blockers. Reconcile attempt resources before entering `In Progress` from `Todo`/`Rework`, including interrupted recovery; validate every transition and reread it.
3. Reconstruct and audit the entire current deployed outcome from scratch. Prior reports, checklists and cached partial checks do not bound acceptance. Do not fix Product code here.
4. Run required deterministic, integration, live and semantic acceptance against exact current state. Reuse a direct successful result only when source, exact command, environment/release and semantic contract are unchanged. Use native background-terminal waiting; create no polling supervisor, command timeout, arbitrary threshold or alternate Codex home.
5. A finding first reconciles attempt resources, then publishes and byte-for-byte rereads a `remediation-required` semantic handoff. Only afterward create/link its bounded remediation implementation blocker, preserve final-cleanup dependency and return acceptance to `Todo`. After every correction, run a new fresh-thread full pass.
6. After a whole-scope zero-finding pass, derive the required local-flow queue, startup, execution, review and merge durations from exact Linear/GitHub history and render them through `evidence.py baseline`. Publish that baseline as direct provider evidence and require byte-identical readback. Do not estimate missing phases or parse private chat logs.
7. Reconcile attempt resources under the live guard, then publish one `final-boundary` semantic handoff with concise current state, exact commit/environment identities, direct verification summaries, the byte-read baseline evidence URL in its evidence URLs, and any nonempty subset of directly exposed exact known Codex usage counters. Fully paginate and require byte-identical readback. Create no verification receipts, candidate fingerprints, invalidation gates or estimates.
8. Validate `In Progress -> Review` with completed attempt cleanup and local-phase baseline proof, mutate and reread Linear, then stop. This is the only human lifecycle boundary: the human evaluates the deployed result and moves current accepted evidence to `Done`, rejection to `Rework`, or cancels. There is no per-PR human approval.

Attempt-resource cleanup is a mandatory pre-handoff and pre-transition step for success, finding, stale-state, failed, canceled and controlled interrupted outcomes. No status mutation or handoff publication may precede it. An abrupt process loss publishes nothing; the next guarded attempt repeats the idempotent cleanup before recovery.

Every preview/handoff states the canonical-root guard lifecycle and direct evidence produced. Delete transient inputs only after final provider readback; process exit releases the guard.
