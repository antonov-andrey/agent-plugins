# Accept Linear Outcome

Accept one `task:acceptance` / `evidence` issue in a fresh `gpt-5.6-sol` max-reasoning thread. Read `../../references/manual-workflow.md`, the complete active Project graph, exact source revision, every resulting stable owner, merged commits, current external state and direct evidence.

1. Set canonical `LINEAR_AGENT_WORKSPACE_ROOT`, acquire the exact issue process-lifetime guard before dispatch/status mutation, and hold it through nested cleanup and final provider readback. Process exit afterward is the only release.
2. Fully reread Linear, run dispatch, require Project `In Progress`, issue `Todo`/`In Progress`/`Rework`, exact acceptance role/evidence delivery and no blockers. Validate every transition and reread it.
3. Reconstruct and audit the entire current deployed outcome from scratch. Prior reports, checklists and cached partial checks do not bound acceptance. Do not fix Product code here.
4. Run required deterministic, integration, live and semantic acceptance against exact current state. Reuse a direct successful result only when source, exact command, environment/release and semantic contract are unchanged. Use native background-terminal waiting; create no polling supervisor, command timeout, arbitrary threshold or alternate Codex home.
5. A finding creates/links a bounded remediation implementation blocker, preserves final-cleanup dependency, publishes and byte-for-byte rereads a `remediation-required` semantic handoff, and returns acceptance to `Todo`. After every correction, run a new fresh-thread full pass.
6. After a whole-scope zero-finding pass, reconcile attempt resources under the live guard and publish one `final-boundary` semantic handoff with concise current state, exact commit/environment identities, direct verification summaries, evidence URLs and only directly exposed exact Codex usage counters. Fully paginate and require byte-identical readback. Create no verification receipts, candidate fingerprints, invalidation gates or estimates.
7. Validate `In Progress -> Review`, mutate and reread Linear, then stop. This is the only human lifecycle boundary: the human evaluates the deployed result and moves current accepted evidence to `Done`, rejection to `Rework`, or cancels. There is no per-PR human approval.
8. When the issue owns local-flow baseline acceptance, derive queue, startup, execution, review and merge durations from exact Linear/GitHub history and render them through `evidence.py baseline`. Do not estimate missing phases or parse private chat logs.

Every preview/handoff states the canonical-root guard lifecycle and direct evidence produced. Delete transient inputs only after final provider readback; process exit releases the guard.
